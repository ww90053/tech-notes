Kubernetes (K8s) 的生態系非常龐大，專有名詞眾多。為了方便理解，我將這些名詞依據核心架構（重要）、日常開發與維運（常用），以及進階管理與擴充（一般 / 進階）三個等級進行分類與整理。

### 第一級：重要 (核心架構與基礎概念)

這些是構成 K8s 運作的最底層與最核心的元件，無論你是開發還是維運，都必須深刻理解的概念。

- Cluster (叢集)： K8s 的基本運作單位，由一組實體或虛擬機器組成，用於執行容器化應用程式。
- Node (節點)： 叢集中的工作機器（VM 或實體機）。分為負責管理的 Master Node（控制節點）與負責執行應用的 Worker Node（工作節點）。
- Pod： K8s 中可創建與管理的最小可部署單元。一個 Pod 可以包含一個或多個緊密關聯的容器（Container），它們共享網路 IP 與儲存資源。
- Control Plane (控制平面)： 負責管理叢集全域狀態的核心大腦，通常運行在 Master Node 上。包含以下核心元件：
- kube-apiserver： K8s 的核心大門，所有內部與外部的請求（API 呼叫）都必須經過它。
- etcd： 一個高可用的分散式鍵值儲存（Key-Value Store），保存了整個叢集的狀態與配置資料。
- kube-scheduler (調度器)： 負責監控新建立但尚未分配節點的 Pod，並根據資源需求將其分配到最適合的 Node 上。
- kube-controller-manager (控制器管理器)： 負責運行各種控制器（如節點控制器、副本控制器），確保叢集的實際狀態與期望狀態保持一致。


- kubelet： 運行在每個 Node 上的代理程式，負責確保容器在 Pod 中正常運行。
- kube-proxy： 運行在每個 Node 上的網路代理，負責維護網路規則，實現 K8s 的服務發現與負載平衡。
- Container Runtime (容器執行環境)： 負責真正拉取映像檔並執行容器的軟體，例如 containerd、CRI-O 或 Docker。

### 第二級：常用 (日常開發、部署與網路設定)

這些是你每天寫 YAML 檔、部署應用程式、設定網路與儲存時最常使用的資源物件（Resources）。

1. 負載與應用程式管理 (Workloads)

- Deployment (部署)： 最常用的無狀態應用控制器。負責管理 ReplicaSet，支援滾動更新（Rolling Update）與版本回退。
- ReplicaSet (副本集)： 確保指定數量的 Pod 副本隨時處於運行狀態。通常由 Deployment 自動管理，很少直接手動建立。
- StatefulSet (有狀態集)： 用於管理「有狀態」的應用程式（如資料庫），保證 Pod 的部署順序、穩定的網路識別碼與持久化儲存。
- DaemonSet (守護行程集)： 確保在叢集中的「每一個」（或符合條件的）Node 上都運行一個特定的 Pod 副本（常用於日誌收集、監控代理）。
- Job (任務)： 負責執行一次性任務，確保指定數量的 Pod 成功完成工作後就結束。
- CronJob (排程任務)： 類似 Linux 的 cron，用於在特定時間或週期性地執行 Job。

2. 網路與服務發現 (Networking)

- Service (服務)： 為一組動態變化的 Pod 提供一個統一的固定 IP 與 DNS 名稱。常見類型包含：
- ClusterIP： 預設類型，僅供叢集內部存取。
- NodePort： 在每個 Node 的特定 Port 上開放服務，可供外部存取。
- LoadBalancer： 向雲端供應商申請外部負載平衡器。
- Ingress： 管理外部存取叢集內部 HTTP/HTTPS 服務的路由規則（類似反向代理，如 Nginx）。需要搭配 Ingress Controller 才能運作。
- Endpoint (端點)： 記錄了 Service 對應到的實際 Pod IP 與 Port。

3. 儲存與配置 (Storage & Config)

- ConfigMap (配置對映)： 用於儲存非機密的設定檔（Key-Value），讓應用程式代碼與設定分離。
- Secret (機密字典)： 用於儲存敏感資訊（如密碼、憑證、Token），內容會經過 Base64 編碼。
- Volume (儲存卷)： 掛載到 Pod 中的目錄，生命週期與 Pod 綁定。
- PersistentVolume (PV, 持久卷)： 叢集層級的儲存資源（如雲端硬碟、NFS），生命週期獨立於 Pod 之外。
- PersistentVolumeClaim (PVC, 持久卷宣告)： 開發者對 PV 儲存資源的「申請單」，K8s 會自動將 PVC 綁定到合適的 PV。
- StorageClass (儲存類別)： 定義動態配置 PV 的範本，讓 K8s 可以根據 PVC 的請求自動建立儲存資源。

4. 組織與中介資料 (Organization)

- Namespace (命名空間)： 在單一實體叢集中劃分出的虛擬叢集，用於資源隔離（例如分出 project-a, project-b 環境）。
- Label (標籤)： 附加在 K8s 物件上的鍵值對，用於識別與分類資源。
- Selector (選擇器)： 透過 Label 來篩選和關聯特定的資源（例如 Service 用 Selector 找到對應的 Pod）。
- kubectl： 與 K8s 叢集互動的最核心命令列工具。

### 第三級：一般 (進階管理、安全、擴充與治理)

這些名詞在進行叢集維護、效能最佳化、權限控管或架構擴充時才會頻繁接觸。

1. 擴縮容與調度策略 (Scaling & Scheduling)

- HPA (Horizontal Pod Autoscaler)： 根據 CPU、記憶體或自定義指標，自動增減 Pod 的數量（水平擴縮）。
- VPA (Vertical Pod Autoscaler)： 自動調整 Pod 所需的 CPU 與記憶體請求上限（垂直擴縮）。
- Cluster Autoscaler： 當 Node 資源不足以調度新 Pod 時，自動向雲端供應商請求增加 Node 節點。
- Taint (污點) & Toleration (容忍度)： Taint 設在 Node 上以「排斥」特定的 Pod；Toleration 設在 Pod 上，讓 Pod 可以「容忍」並被調度到有污點的 Node 上。
- Affinity / Anti-Affinity (親和性 / 反親和性)： 規定 Pod 偏好部署在哪個 Node 上，或者偏好與哪些 Pod 部署在一起 / 分開部署。

2. 安全與權限控制 (Security & Access)

- RBAC (Role-Based Access Control)： 基於角色的存取控制，K8s 預設的權限管理機制。
- Role / ClusterRole： 定義在特定 Namespace (Role) 或全叢集 (ClusterRole) 中可以執行哪些操作的規則。
- RoleBinding / ClusterRoleBinding： 將 Role 或 ClusterRole 的權限綁定到特定的使用者或 ServiceAccount。
- ServiceAccount (服務帳號)： 給 Pod 內部運行的應用程式使用的身分，用於與 K8s API 溝通。
- NetworkPolicy (網路策略)： 叢集內的防火牆，定義哪些 Pod 之間可以互相通訊。

3. 容器生命週期與模式 (Lifecycle & Patterns)

- Liveness Probe (存活探針)： 檢查容器是否處於正常運作狀態，若失敗則 K8s 會重啟該容器。
- Readiness Probe (就緒探針)： 檢查容器是否已經準備好接收流量，若失敗則從 Service 的 Endpoint 中暫時移除。
- Startup Probe (啟動探針)： 專為啟動緩慢的應用設計，成功前會暫停另外兩種探針。
- Init Container (初始化容器)： 在應用程式主容器啟動前執行的容器，通常用於前置作業（如資料庫連線測試、權限設定）。
- Sidecar (邊車模式)： 在同一個 Pod 中，除了主應用容器外，再掛載一個輔助容器（如負責收集 Log 或擔任 Service Mesh 代理）。

4. 資源治理與介面標準 (Governance & Interfaces)

- ResourceQuota (資源配額)： 限制某個 Namespace 下可以使用的資源總量（如最多只能用 10G 記憶體）。
- LimitRange (限制範圍)： 限制某個 Namespace 內單一 Pod 或 Container 預設的資源請求（Request）與上限（Limit）。
- PDB (PodDisruptionBudget, Pod 中斷預算)： 確保在叢集進行維護（如 Node 升級）時，至少有多少比例的 Pod 必須保持在線，以防服務中斷。
- CRD (Custom Resource Definition, 自定義資源定義)： 允許開發者擴充 K8s 的 API，建立非內建的自定義資源。
- Operator (營運者模式)： 結合 CRD 與自定義控制器，將人類維運專家管理複雜應用的經驗程式化（例如自動備份與修復資料庫的 Operator）。
- Helm： K8s 的套件管理工具（類似 Ubuntu 的 apt 或 Mac 的 brew）。
- CRI / CNI / CSI： K8s 為了與第三方軟體解耦所定義的標準介面：
- CRI (Container Runtime Interface)： 容器執行環境介面。
- CNI (Container Network Interface)： 容器網路介面（如 Calico, Flannel）。
- CSI (Container Storage Interface)： 容器儲存介面。
