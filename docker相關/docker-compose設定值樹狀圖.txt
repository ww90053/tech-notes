docker-compose.yml (終極全選項暨推薦值樹狀圖)
├── version: '3.8' ⚪【進階可選】(新版 Compose V2 已可省略)
│
├── services: 🔴【必要】(整個專案至少要定義一個服務區塊)
│   └── [service_name]: 🔴【必要】(自訂的服務/容器名稱，例如 mailpit)
│       │
│       │  【 1. 基礎建置與映像檔控制 】
│       ├── image: 🔴【二選一必要】(指定要下載的現成 Image 標籤)
│       ├── build: 🔴【二選一必要】(若不用現成 Image，則指定現場建置)
│       │   ├── context: 🔴【若用 build 則為必要】(指定 Dockerfile 所在的資料夾路徑)
│       │   ├── dockerfile: ⚪【進階可選】(自訂 Dockerfile 的檔名，預設為 Dockerfile)
│       │   ├── args: ⚪【進階可選】(建置 Image 時傳入的環境變數/參數)
│       │   ├── target: ⚪【進階可選】(多階段建置時，指定建置到哪一個階段為止)
│       │   ├── cache_from: ⚪【進階可選】(指定快取映像檔來源以加速建置)
│       │   └── network: ⚪【進階可選】(建置過程中，下載套件時使用的網路模式)
│       ├── container_name: 🟡【強烈建議】(自訂容器在系統執行的實體名稱，方便辨識)
│       ├── restart: 🟡【強烈建議】(重啟策略選擇)
│       │   ├── 🌟 unless-stopped (最推薦：除非手動停止，否則不論當機或主機重啟都會自動復活)
│       │   ├── always (主機重啟或容器異常就無限重啟，即使用戶手動停止它，重啟 Docker 後它還是會被強行拉起來)
│       │   ├── on-failure (只有在程式碼異常崩潰 Exit Code 非 0 時才重啟)
│       │   └── no (預設值：不論任何原因停止，都不自動重啟)
│       ├── pull_policy: ⚪【進階可選】(映像檔拉取策略)
│       │   ├── 🌟 missing (最推薦/預設：本機沒有此 Image 才去網路上拉，省時省頻寬)
│       │   ├── always (每次啟動都去網路檢查是否有新版並強制重新下載)
│       │   └── never (絕對不下載，只使用本機現有的 Image，若本機沒有就直接報錯)
│       │
│       │  【 2. 網路與連接埠進階控制 】
│       ├── ports: 🟡【實用可選】(若這個網站要對外開放，必須對應 [主機Port]:[容器Port])
│       │   └── - "80:80/tcp" ⚪【進階可選】(傳輸協定選擇：🌟 tcp [預設 / 網頁服務首選]、udp [適用於串流或高頻傳輸])
│       ├── expose: ⚪【進階可選】(僅宣告內部開放的連接埠，絕不暴露給外網主機)
│       ├── networks: 🟡【強烈建議】(多容器要互相通訊時，指定加入同一個網路)
│       │   └── [network_name]:
│       │       ├── aliases: ⚪【進階可選】(在此網路圈子中的別名/多重虛擬網域)
│       │       └── ipv4_address: ⚪【進階可選】(微服務架構中，強行指定容器的固定內部 IP)
│       ├── network_mode: ⚪【進階可選】(網路架構切換)
│       │   ├── 🌟 bridge (預設/最推薦：使用傳統獨立隔離網路)
│       │   ├── host (拔除隔離層，直接共用主機網卡與所有連接埠，追求極致效能時使用)
│       │   ├── container:[name] (強制共用另一個既有容器的網路空間)
│       │   └── none (完全關閉網路卡，達到絕對的物理隔離)
│       ├── hostname: ⚪【進階可選】(自訂容器內部作業系統的電腦名稱)
│       ├── domainname: ⚪【進階可選】(自訂容器內部作業系統的網域名稱)
│       ├── extra_hosts: ⚪【進階可選】(手動強行修改容器內部的 /etc/hosts 檔案)
│       │
│       │  【 3. 儲存與資料夾掛載 】
│       ├── volumes: 🟡【強烈建議】(資料持久化！把資料庫或網頁檔案留在主機上，避免刪容器時資料消失)
│       │   └── - type: bind ⚪【進階可選】(掛載類型選擇：🌟 bind [直連主機資料夾，網頁開發首選]、volume [具名磁碟卷，資料庫首選]、tmpfs)
│       ├── tmpfs: ⚪【進階可選】(將特定目錄掛載在主機的記憶體中，讀寫極快，重啟後資料消失)
│       │
│       │  【 4. 環境變數、安全與憑證 】
│       ├── environment: 🟡【實用可選】(設定容器內的變數，如時區 TZ=Asia/Taipei 或資料庫密碼)
│       ├── env_file: 🟡【實用可選】(當變數太多時，統一從外部檔案如 .env 載入)
│       ├── secrets: ⚪【進階可選】(企業級敏感資料管理，將加密憑證或私鑰安全傳入容器)
│       ├── configs: ⚪【進階 Brodcast 】(將外部應用程式的設定檔統一注入至容器中)
│       │
│       │  【 5. 權限、安全防護與 Linux 核心微調 】
│       ├── user: ⚪【進階可選】(指定容器內執行的 UID:GID，避免用高風險的 root 執行)
│       ├── privileged: ⚪【進階可選】(給予容器極高的主機核心控制特權，一般為安全考量都不開啟)
│       ├── cap_add: ⚪【進階可選】(針對 Checkmarx 等弱掃合規，精細開放 Linux 內核部分權限，如 NET_ADMIN)
│       ├── cap_drop: ⚪【進階可選】(嚴格封鎖、移除 Linux 內核的特定權限)
│       ├── security_opt: ⚪【進階可選】(配置進階安全防護系統，如 AppArmor, SELinux)
│       ├── sysctls: ⚪【進階可選】(調校 Linux 核心底層網路或記憶體參數，如調整最大連線數)
│       ├── ulimits: ⚪【進階可選】(覆寫 Linux 系統最大檔案開啟數限制，防止高併發時系統卡死)
│       ├── stop_signal: ⚪【進階可選】(指定關閉容器時發送的 Linux 訊號，🌟 SIGTERM [正常關閉安全退出]、SIGKILL [立刻強制斬殺])
│       ├── stop_grace_period: ⚪【進階可選】(緩衝停止時間，預設 10s，資料庫通常調整為 1m30s，確保資料安全寫入硬碟)
│       │
│       │  【 6. 依賴關係與健康檢查 】
│       ├── depends_on: 🟡【實用可選】(控制啟動順序，確保資料庫完全啟動後，網站才跟著啟動)
│       │   └── [another_service]:
│       │       └── condition: ⚪【進階控制】(依賴狀態選擇：service_started [對方容器開了就行]、🌟 service_healthy [對方必須健康檢查完全通過才開我])
│       ├── healthcheck: ⚪【進階可選】(容器自我檢查機制，定時執行指令確保網站沒有變成殭屍死機)
│       │   ├── test: ["CMD", "curl", "-f", "http://localhost"]
│       │   ├── interval: 30s (檢查間隔時間)
│       │   ├── timeout: 10s (超時判定)
│       │   ├── retries: 3 (允許連續失敗幾次)
│       │   └── start_period: 40s (啟動緩衝期，期間內失敗不列入計算)
│       │
│       │  【 7. 系統日誌與硬體周邊 】
│       ├── logging: 🟡【強烈建議】(限制日誌最大容量與檔案數量，避免硬碟幾年後被 Log 塞爆)
│       │   ├── driver: 🟡【日誌儲存模式選擇】
│       │   │     ├── 🌟 json-file (最推薦/預設：以標準 JSON 檔案儲存於本機，最好維護)
│       │   │     ├── local (自定義輕量本機儲存)
│       │   │     └── syslog / journald / fluentd / gelf (企業級集中式日誌管理，專門對接 ELK 或 Splunk)
│       │   └── options: { max-size: "10m", max-file: "3" }
│       ├── devices: ⚪【進階可選】(將主機實體裝置對應進容器，如 IoT 監控要讀取的 USB 序列埠 /dev/ttyUSB0)
│       │
│       │  【 8. 資源限制與叢集部署管理 】
│       └── deploy: ⚪【進階可選】(高可用架構、K8s/Swarm 叢集或硬體限制專用區塊)
│           ├── mode: ⚪【部署模式選擇】(🌟 replicated [複製副本模式，自訂容器數量]、global [全節點模式，每台實體機強行各跑一台])
│           ├── replicas: 3 (高可用負載平衡下，這個網站一鍵啟動的副本數量)
│           ├── resources: (硬體上限配置)
│           │   ├── limits: (防止程式記憶體洩漏榨乾主機的最高上限)
│           │   │   ├── cpus: '2.00' (最多調用 2 核心 CPU)
│           │   │   └── memory: 4G (最多調用 4GB 記憶體)
│           │   └── reservations: (基本保障預留，如指定呼叫 NVIDIA GPU 顯示卡)
│           ├── restart_policy: (叢集環境專用的重啟規則)
│           ├── update_config: (無痛滾動更新策略，例如一次只更新一台，維持服務中斷時間為零)
│           └── rollback_config: (當更新失敗時，自動回復成上一個穩定版本的策略)
│
├── networks: 🟡【實用可選】(如果在上面的 services 中有自訂網路，這裡就必須定義其規格)
│   └── [network_name]: 🔴【若有 networks 則此區塊名稱必要】
│       ├── driver: 🟡【網路驅動模式選擇】
│       │     ├── bridge (單機多網站架構唯一推薦：建立獨立主機內網，安全、高隔離)
│       │     ├── overlay (分散式高可用叢集推薦：跨多台實體主機的容器大區域網路)
│       │     ├── host (直接使用主機網路，無隔離)
│       │     └── macvlan (賦予容器實體 MAC 與同區網實體 IP，常用於 IoT 模擬)
│       ├── driver_opts: ⚪【進階可選】(微調底層虛擬網卡的進階參數)
│       ├── ipam: ⚪【進階可選】(IP 位址管理，用來切割子網段 subnet，如 172.20.0.0/16)
│       ├── name: 🟡【實用可選】(強制指定主機實體的網路名稱，方便跨專案連線)
│       ├── external: 🟡【實用可選】(宣告是否直接引入主機上其他地方已經建好的網路)
│       └── internal: ⚪【進階可選】(高資安設定：限制此網路完全封閉，裡面的容器絕不能連到外網)
│
├── volumes: 🟡【實用可選】(如果在上面的 services 中使用的是「具名磁碟卷」，這裡就必須定義)
│   └── [volume_name]: 🔴【若有具名 volumes 則此名稱必要】
│       ├── driver: 🟡【儲存驅動模式選擇】
│       │     ├── 🌟 local (最推薦/預設：直接儲存在本機硬碟中，速度最快、穩定)
│       │     └── nfs / flocker (企業儲存首選：直接透過網路掛載遠端 NAS、SAN 或雲端儲存)
│       ├── driver_opts: ⚪【進階可選】(設定遠端掛載儲存設備時的連線密碼、協定或權限參數)
│       ├── name: 🟡【實用可選】(強制指定主機實體的磁碟卷名稱)
│       └── external: 🟡【實用可選】(引入主機上已存在的舊資料卷)
│
├── secrets: ⚪【進階可選】(全域安全憑證定義區，供多個服務共同掛載)
└── configs: ⚪【進階可選】(全域共用設定檔定義區，供多個服務共同掛載)
